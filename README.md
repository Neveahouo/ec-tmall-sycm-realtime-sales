# 生意参谋实时销售数据采集

定时抓取淘宝/天猫「生意参谋」首页的实时经营数据（支付金额、访客数、支付买家数），
按时间点写入飞书表格，并把带「时点数据 + 时段累计」的卡片推送到飞书群。

用于大促期间（如 618、双 11）按 5 分钟粒度留档销售进度，替代人工盯屏幕 + 手动记数。

---

## 工作原理

生意参谋对自动化调用有较强风控（接口签名、滑块验证、行为检测），直接爬接口很容易被拦。

本项目采用**真人会话 + 纯视觉读取**的方式规避：

1. 用**独立用户目录**、以 `--remote-debugging-port` 启动一个正常浏览器（Edge/Chrome）；
2. 人工在这个窗口里登录生意参谋，登录态就存在该目录里，可长期复用；
3. 脚本通过 Selenium 的 `debuggerAddress` **连接这个已经在跑的浏览器**（不新开浏览器、不注入 UA、不改指纹）；
4. 只读取页面**已经渲染出来的文本**，等同人工看一眼，不发起任何数据接口请求；
5. 到点前刷新页面，到点后读数，写入飞书表格并推送卡片。

> 注意：这是给「自己的账号、自己的数据」做自动记录用的工具，不用于采集他人数据或绕过平台权限。

---

## 功能

- 按指定时间点（如 20:00、20:05、20:10…）自动采集，时间点可用参数或 `.env` 配置
- 首次采集作为**基准**，后续每个时间点自动计算**时段累计**（当前 - 基准）
- 结果写入飞书表格指定行：时点值 + 时段累计值，不覆盖其它列
- 推送飞书卡片到群，含两张表：时点数据、时段累计（带分钟数）
- 识别失败自动刷新重试 3 次，仍失败则截图留证到 `logs/`
- 全程日志落盘 `logs/YYYY-MM-DD.log`
- 支持 `--dry-run`（只打印不写表不推送）和 `--once`（只采一次验证环境）

## 快速开始

### 1. 安装依赖

```powershell
python -m pip install -r requirements.txt
```

### 2. 启动 debug 浏览器

```powershell
.\start_browser_debug.ps1
# 或双击 start_browser_debug.bat
# 指定 Chrome： .\start_browser_debug.ps1 -Browser chrome
```

脚本会打印 `debug 端口：9222（...）` 表示启动成功。

> 若本机已有浏览器在运行，端口可能不生效。**先完全退出浏览器**（含托盘后台进程）再启动。

### 3. 登录生意参谋

在弹出的窗口里登录「三只松鼠旗舰店」生意参谋，停留在首页即可。
登录态保存在 `browser_profile/`，下次启动通常无需再登录，直到 cookie 过期。

### 4. 配置

```powershell
Copy-Item .env.example .env
notepad .env
```

按下方「配置说明」填写。**`.env` 已被 `.gitignore` 排除，不要提交到仓库。**

### 5. 验证环境

```powershell
python run.py --once
```

能打印出「当前采集结果」且三个值都大于 0，说明链路通了。

### 6. 正式运行

```powershell
# 指定时间点
python run.py --time-points "20:00,20:05,20:10,20:15"

# 或按起始时间 + 间隔 + 个数自动展开
python run.py --start 20:00 --interval 5 --count 12
```

脚本会先抓一次**基准**（写入 `BASE_ROW` 行），然后逐个时间点采集、写表、推卡片。

## 配置说明（`.env`）

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `FEISHU_APP_ID` | 飞书自建应用 App ID | `cli_a938xxxx` |
| `FEISHU_APP_SECRET` | 应用 App Secret（**敏感，勿提交**） | `0VkI6xxxx` |
| `FEISHU_CHAT_ID` | 卡片推送目标群 chat_id | `oc_2cffxxxx` |
| `SHEET_URL` | 飞书表格完整链接 | `https://xx.feishu.cn/sheets/xxxx` |
| `SHEET_ID` | 工作表 ID（链接 `?sheet=` 后的值） | `QpR9wW` |
| `BASE_ROW` | 兜底起始行：A 列没有任何标签时从这个行号开始写 | `2` |
| `SHEET_WRITER` | `larkcli` 或 `api` | `larkcli` |
| `BROWSER` | `edge` 或 `chrome` | `edge` |
| `DEBUG_PORT` | 浏览器 debug 端口，与启动器一致 | `9222` |
| `LOGIN_TIMEOUT` | 等待人工登录的秒数 | `300` |
| `TIME_POINTS` | 时间点列表（逗号分隔） | `20:00,20:05` |
| `CARD_TITLE` | 卡片标题前缀 | `天猫时段销售情况` |

### 两种表格写入方式

| 方式 | 前提 | 适用 |
| --- | --- | --- |
| `larkcli`（默认） | 本机已安装并登录 `lark-cli` | 当前可直接使用，走用户本人权限 |
| `api` | 飞书应用开通 `sheets:spreadsheet` / `drive:drive` 权限，且应用被加为表格协作者 | 换机器部署更轻，不依赖 lark-cli |

开通 `api` 方式：在飞书开放平台应用后台申请上述权限 → 管理员审核通过 → 把机器人加入目标表格协作者。
未开通时调用会报 `99991672 / Access denied`。

## 表格结构约定

| 列 | 含义 |
| --- | --- |
| A | 时间点（如 `20:05`，由你或公式维护） |
| B | 时点支付金额 |
| C | 时点访客数 |
| D | 时点支付买家数 |
| E | 时段支付金额（当前 - 基准） |
| F | 时段访客数 |
| G | 时段支付买家数 |

- **按 A 列时间标签定位写入行**：表格 A 列已有 `14:50`、`20:05` 等标签时，直接写入对应行，不会错位；
- A 列没有该时间点时，取**第一个空行**写入，并同时补上 A 列标签；
- 整列都无标签时，从 `BASE_ROW` 起依次追加；
- 基准行（E/F/G 写 0）同样按标签匹配（标签为采集到的基准时间）
- 脚本只写 A 列（仅当该行 A 为空）和 B–G 列，不碰其它列（如去年对比数据）

## 常见问题

**1. 连接不上浏览器 / 端口 9222 无响应**
浏览器已有一个正常实例在跑时，新加的 `--remote-debugging-port` 会被忽略。
先彻底退出浏览器（任务管理器确认无残留），再用启动器启动。

**2. 提示等待登录超时**
打开浏览器窗口手动登录；若出现滑块验证，人工拖动通过即可（脚本不会去破解验证码）。
登录成功后脚本会自动继续，无需重启。

**3. 识别结果为 0**
说明页面没停在「实时」概览，或页面结构变了。
脚本会自动刷新重试并截图到 `logs/`；打开截图确认位置。必要时用 `--once` 单独排查。

**4. 某项数值小于基准，被跳过**
说明该时点识别异常（或数据被平台回滚）。脚本不会写入错误增量，会记日志并继续下一个时间点。

**5. 电脑休眠 / 锁屏**
休眠会中断采集。需在电源设置中关闭睡眠，并保持浏览器窗口不关闭。

**6. 时间段跨零点**
脚本按「基准时间 - 当前时间」计算分钟数，跨零点会按次日处理，增量为正。

## 安全提醒

- **不要把 `FEISHU_APP_SECRET` 提交到仓库**。本仓库通过 `.env` + `.gitignore` 隔离；
  如果曾把密钥贴到聊天、文档或公开仓库，请到飞书开放平台**重置 App Secret**。
- `browser_profile/` 内含登录 cookie，同样不要提交。
- 建议仓库设为 **Private**。
- 卡片不包含账号密码等敏感信息；日志仅记录数值与状态。

## 部署到常开机器

1. 在目标机器上克隆仓库、`pip install -r requirements.txt`
2. 复制 `.env.example` 为 `.env` 并填写
3. 用启动器启动浏览器，人工登录一次生意参谋
4. 建议用「任务计划程序」在每天固定时间启动：
   - 程序：`python`
   - 参数：`run.py --start 20:00 --interval 5 --count 24`
   - 起始于：仓库根目录
   - 勾选「不管用户是否登录都要运行」时注意：**必须有可用的桌面会话**，否则浏览器无法交互

> 更稳妥的做法：机器保持登录状态、浏览器常开，只让脚本按时间点跑，避免每天重启浏览器导致登录态波动。

## 已知限制

- 依赖页面文本结构，生意参谋改版后可能需要调整 `sycm/extractor.py` 中的正则
- 需要人工完成一次登录（含可能的滑块验证）
- 采集精度受页面刷新与数据更新延迟影响，通常为分钟级
- 同一浏览器窗口同一时间只建议跑一个采集任务
